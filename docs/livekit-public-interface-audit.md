# LiveKit instrumentation interface audit

Audit against the installed published declarations and implementations of
`@livekit/agents` and `@livekit/agents-plugin-openai` 1.9.1 and 1.10.0.
These changes remain local for review; no compatibility beyond that matrix is
claimed. Public visibility here follows the published declarations, not whether
JavaScript happens to permit property access.

| Boundary                                                                                        | Assessment and action                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client ownership inferred with `Function.toString()` / `#client` method text                    | Removed. Observe public adapter constructor options, independently of integration activation. Handle injected clients and default SDK construction separately.                                                                                                                                                                                                                                     |
| OpenAI resource `_client`                                                                       | Removed. Check public client methods and operation resources. No resource internals are read.                                                                                                                                                                                                                                                                                                      |
| LiveKit LLM stream `client`                                                                     | Declared private in the inference stream, despite its ordinary JS property. Removed this dependency. The actual plugin constructor now supplies ownership; custom e2e clients use public injection rather than changing stream internals.                                                                                                                                                          |
| `_conversationItemAdded`                                                                        | Replaced in both paths by public `AgentSession.emit` and its documented `conversation_item_added` event. This event reports handoffs before the new activity starts.                                                                                                                                                                                                                               |
| `telemetry.tracer.startSpan/startActiveSpan/startActiveSpanSync`, OTel span methods             | Public. Retain native-span observation; preserve the application's tracer provider and sampling.                                                                                                                                                                                                                                                                                                   |
| `recognize`, `chat`, `synthesize`, `stream`, iterator methods, `pushFrame`, `pushText`, `close` | Public model APIs. Retain shared method wrapping and normal return/stream behavior.                                                                                                                                                                                                                                                                                                                |
| Stream `run` and producer `queue.put`                                                           | Declared **protected**, not public. Narrow, documented adapter extension bridge: no public event exposes per-attempt partial output before buffering. Observe writes without adding a consumer. Consumer observation alone misattributes delayed chunks after retries and cannot retain failed partial output. Prefer an upstream public attempt/output observer if introduced.                    |
| STT `_recognize` identity                                                                       | Protected base adapter extension (public in the qualified OpenAI plugin declaration). Used only to avoid assigning base constructor ownership to a subclass replacing recognition. No source-text inspection. An upstream per-operation ownership accessor would remove this check.                                                                                                                |
| Session `_startImpl`, activity `_startSessionImpl`, `_pipelineReplyTaskImpl`                    | Private, version-qualified lifecycle bridge retained. Native session spans are created inside public `start`, and the implementation hooks establish scope after creation but before child client work. Public node APIs alone do not give all of this native timing/turn/tool context. Replacing these requires a broader lifecycle redesign and matrix verification, not a simple method rename. |
| Session `closeImpl`                                                                             | Private, retained with a reason: public `close()` alone misses autonomous shutdown/error paths. This hook also awaits recording finalization before the LiveKit job exits. Public close events occur too late to guarantee that awaited cleanup.                                                                                                                                                   |
| Activity/input/turn/recognition callbacks and private native span/turn fields                   | Private/internal compatibility bridge retained for actual recognition context, original turn membership, playback ownership, and native relationships. Receipt events alone cannot establish recognition duration. Public session/model APIs are preferred for client work; these hooks supply native framework associations unavailable on those APIs.                                            |
| Job `_redactionEnabled`                                                                         | Internal privacy dependency retained conservatively. Public `getJobContext(false)` is used to obtain context; environment flags, native redaction attributes, and session/job policy remain independent restrictions. Replacing this field needs a public LiveKit effective-redaction accessor, not omission of the project restriction.                                                           |

The remaining private lifecycle dependencies are concentrated in the vendored
LiveKit surface, normal auto configuration, and manual compatibility hooks. The
auto range remains `>=1.9.1 <1.11.0`; the same supported range is documented for
manual wrapping. Do not widen it without qualification. Public APIs do not
currently expose every native association needed by the v3 audio trace schema.

Recommended upstream requests: a public effective client/transport accessor, a
public per-attempt output observer, and lifecycle/turn context plus effective
redaction accessors. Those would let us remove the remaining bridges without
inventing durations, losing native associations, or bypassing privacy settings.

Ownership is qualified for the stock OpenAI cascade adapter methods, including
custom clients supplied to their public constructors. A subclass that replaces
an operation can ignore or replace the constructor client; arbitrary delegation
inside that replacement cannot be recovered from constructor options. Such
adapters need a documented exposed client/transport boundary or separate
qualification. This is the main reason to prefer an upstream per-operation
accessor over claiming universal custom-adapter inference.
